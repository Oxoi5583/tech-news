# 《Crazy Taxi: World Tour》：如何把 25 年前的遊戲「らしさ」拆成可重新設計的原則

[TOC]

## 這篇在談甚麼

《Crazy Taxi》距離上一款主要系列新作已約 25 年。新作團隊中，真正參與過舊作的人極少；創意製作人菅野顕二估計，99% 成員都不是當年的原班人馬。

這令「做續作」變成一個很實際的設計問題：如果不能靠原班人馬的默契，也不能只把 2000 年左右的機制原封不動搬回來，那麼甚麼東西才令一款遊戲仍然是《Crazy Taxi》？

AUTOMATON 的前後篇訪談最值得讀的地方，就是團隊沒有把答案停留在「音樂很重要」「要有速度感」這類品牌描述，而是透露了幾個可以實際影響規則、地圖與製作流程的判斷原則。

## 先做錯一次，才找出真正的核心

新作早期曾從「現實中的計程車」出發，車速也比現在慢。實際做出來後，團隊的判斷很直接：不好玩，而且不像《Crazy Taxi》。

他們於是重新集合團隊討論舊作究竟有甚麼不可失去，最後重新抓回幾個元素：

- 時間限制帶來的持續壓力；
- 在城市中高速亂衝的體驗；
- 音樂與操作共同形成的 Groove；
- 玩家很快便能理解自己應該做甚麼；
- 即使加入新玩法，也要維持「笑著開車」而不是嚴肅駕駛的情緒。

這個過程比「尊重原作」更具體。團隊其實先做了一個合理但錯誤的 interpretation，再透過 Prototype 發現：**表面題材是計程車，不代表遊戲的核心是模擬計程車。**

因此所謂保存 IP Identity，不是列一張舊機制 Checklist，而是先找出舊機制當年共同製造了甚麼玩家狀態。

## 「加點法」：不要因玩家沒有照標準答案玩而懲罰他

菅野給團隊的一個明確要求，是不要採用「減點法」，而要盡量以「加點法」評價玩家。

減點式設計很容易變成：

```text
Designer 定義最佳路線／最佳駕駛方式
        ↓
玩家偏離
        ↓
扣分／失敗／效率下降
```

但《Crazy Taxi》希望的是：

```text
玩家找到自己的跑法
        ↓
做出有趣、有效或高技巧的行為
        ↓
系統給予正向回饋
```

例如，一個玩家可以漂亮地使用 Drift 與技巧把乘客送到目的地；另一個玩家也可以一路撞車、以速度硬闖。兩者看起來完全不同，但團隊希望系統都承認它們是成立的玩法。

這不是「沒有規則」或「甚麼都可以」。目的地、時間限制和任務仍然構成約束；差別在於系統盡量不把一種 Designer 想像中的標準過程當成唯一正解。

因此可以把它理解成：**約束 Outcome，但不要過度約束玩家到達 Outcome 的 Style。**

## 「自由に感じさせる不自由さ」：自由感不是選項數量

菅野談地圖時提出「自由に感じさせる不自由さ」——讓玩家感到自由的限制。

他的例子是：100 種果汁理論上比 5 種更自由，但選擇過多時，人反而更難判斷自己要甚麼。地圖也是一樣。如果所有方向、所有空間都具有同等可能性，玩家雖然形式上自由，實際上可能沒有足夠資訊形成決策。

《World Tour》的地圖因此不是追求最大面積，而是強調高密度的行駛選擇：大路、窄巷和不同路徑都能形成駕駛節奏。

可以把這個原則拆成：

```text
完全開放的空間
→ 可選方向很多
→ 但各方向缺乏清楚差異
→ 決策資訊不足

經過設計的限制
→ 路徑數量較少
→ 每條路徑具有可讀的風險／節奏／技巧差異
→ 玩家更容易產生「這是我選的路」的感覺
```

所以自由感並不等於 Navigation Graph 的 Branching Factor 越高越好。真正重要的是玩家能否理解選項、預測部分後果，並感到自己的選擇造成了不同體驗。

## 地圖追求的是「感覺像現實」，不是複製現實

團隊在日本、歐美等地圖上都研究真實城市，但沒有要求忠實重建。例如日本場景可以有真實商店、高速道路和熟悉的街景元素，同時車距與道路配置仍會為遊戲重新調整。

這與前面的設計原則是一致的：

> 現實是 Reference，不是 Constraint。

目標不是讓玩家量測後發現街道比例正確，而是讓玩家高速經過時仍立即感到「這是日本」「這是那種城市」。

對高速遊戲而言，玩家讀取環境的時間很短，因此地標、道路形狀、密度和節奏往往比精確尺度更重要。

## Multiplayer：不要消除負面情緒，而要讓正向回報更大

新作加入兩類多人玩法，其中一種是 4 名 Taxi 對 2 名 Police 的非對稱規則。

導演百渓曜談 Multiplayer Balance 時提出另一個值得記住的觀點：玩家與玩家接觸一定會同時產生正面與負面情緒。輸掉、被阻礙、被捕本身會令人不快，但如果把所有負面感受消掉，勝利與逆轉也會失去相對強度。

所以他的目標不是：

```text
Negative Emotion → 0
```

而比較接近：

```text
Positive Payoff > Negative Cost
```

這和很多只從 Win Rate 或角色數值談 Balance 的角度不同。百渓首先問的是：**一次 Player-to-Player Interaction 最後留下甚麼情緒？**

這不代表可以用「勝利很爽」合理化任意 Frustration。訪談沒有提供具體數值或 Match Data，因此目前只能把它視為設計方向；真正成立仍需要測試負面體驗的頻率、持續時間與玩家是否能理解失敗原因。

## 音樂不是配樂，而是 Action 的時間標尺

菅野表示自己製作 Action Game 時會採取「曲先行」：先決定音樂，再配合音樂製作遊戲。

理由不是單純營造氣氛。他認為 Action Game 與 Rhythm 密切相關：操作順利時，玩家會進入一種連續的節奏；被打斷時，會直接感到 Groove 被破壞。因此歌曲可以先提供一個整體 Tempo 與情緒標尺，讓團隊判斷遊戲的移動、操作與事件是否具有相同速度感。

在《Crazy Taxi》裡，The Offspring、Bad Religion 等音樂因此不是可以任意替換的背景層。它們參與定義了玩家如何感知速度與動作。

可以把資料流想成：

```text
Music / Tempo / Energy
          ↓
團隊對「這一秒應有多快、多躁動」形成共同感覺
          ↓
Movement / Mission / Feedback / Editing
          ↓
Gameplay Groove
```

這種做法和一般「遊戲完成後再找適合的 BGM」方向相反。音樂在這裡更接近一份非文字的 Game Feel Specification。

## 25 年後的 IP 傳承：保存判斷方式，而不是保存原班人馬

前篇訪談透露，新作團隊幾乎全是沒有參與舊作的新世代成員。這反而產生了一個有趣的製作結構。

當菅野提出自己認為理所當然的《Crazy Taxi》觀念，年輕開發者有時會直接回答「不明白」。於是老成員不能只依靠共同記憶，而必須把模糊的直覺說清楚；新成員再提出現代的實作方式。

這可以看成一種 IP Knowledge 的顯性化：

```text
舊團隊的 Tacit Knowledge
「這樣才像 Crazy Taxi」
        ↓
新成員不理解／質疑
        ↓
必須說明真正想保存的 Experience
        ↓
新團隊可以重新設計 Mechanic
```

有趣的是，這可能比大量舊成員直接沿用過去做法更有利於長期傳承。因為一旦「為甚麼」被迫說清楚，IP Identity 才有機會從個人的手感變成團隊可以共同操作的設計原則。

## 閱讀時需要知道的前提

這是新作上市前的開發者訪談，不是 Postmortem。很多說法目前仍是團隊的設計意圖，而不是已由大量玩家資料驗證的結果。

特別是 Multiplayer 的情緒 Balance、地圖自由度與新舊玩家是否都能感到《Crazy Taxi》的 Identity，都要等實際玩家行為才能判斷。

另外，訪談談的是設計哲學而不是底層技術。雖然開發者提到現代網路技術讓過去難以成立的 Multiplayer 成為可能，但沒有公開 Networking Model、Latency Compensation、Physics Synchronization 或 Server Architecture，因此不應把它當成 Networking 技術資料。

## 我的筆記與延伸

這兩篇最值得留下的，是「續作的忠實」其實可以分成兩層：

```text
Surface Fidelity
舊角色、舊歌曲、舊操作、舊規則

Experience Fidelity
玩家為甚麼笑、為甚麼緊張、為甚麼敢亂來、
甚麼時候感到自己做了一個漂亮的決定
```

如果只保存第一層，很容易做成博物館式 Remake；但如果能把第二層說清楚，Mechanic 反而可以大幅改動。

尤其「加點法」和「有限制的自由」其實可以放在一起理解：兩者都不是最大化形式上的自由度，而是在設計一個**玩家容易產生自我歸因的空間**。路徑不能多到失去可讀性，規則也不能窄到只承認 Designer 的標準答案。玩家最後需要感到：「這是我自己想到、自己做到的。」

另一個有意思的地方是「曲先行」。如果把音樂理解成 Game Feel Specification，它其實是一種跨部門的低精度共同語言：Programmer、Level Designer、Animator 未必能用同一套參數描述「Crazy Taxi 應該有多躁」，但所有人都可以聽同一首歌，感覺目前的遊戲是不是慢了一拍。這不是精確規格，卻可能非常適合定義作品氣質。
