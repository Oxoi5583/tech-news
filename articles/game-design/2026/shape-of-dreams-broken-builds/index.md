# 大人気MOBA風ローグライト『Shape of Dreams』は「バグ由来のぶっ壊れビルド」すら、仕様にしちゃう。開発者が貫く、“壊して楽しい”ゲーム作り

## 這篇在談甚麼

《Shape of Dreams》把 MOBA 式角色操作與 Action Roguelite 的 Build 組合放在一起。開發團隊 Lizard Smoothie 認為作品的重要樂趣之一，就是玩家最後能透過記憶與 Essence 的組合強到近乎「破壞遊戲」。

這篇訪談最值得看的不是成功故事，而是一個很具體的平衡案例：玩家找到一套源自 Bug 的無限 Parry Build，團隊按照「規則一致性」修掉後，卻因玩家強烈反彈而撤回修改，最後甚至因此改變整個團隊對 Balance 的判斷標準。

## 「平衡」不是系統唯一需要保護的價值

Demo 時期，中國玩家社群發現角色 Mist 可以利用會造成自傷傷害的「過負荷のエッセンス」，把自己的傷害 Parry 回去，形成幾乎永久無敵並持續輸出的 Build。

這不是設計者預定的玩法，而是 Bug。

團隊最初按照很合理的工程判斷修正它：自傷不應被 Parry，這樣規則比較一致。但修改推出後，社群強烈要求恢復這套 Build，團隊最後 Rollback Patch，再特別加入例外，讓這個原本的 Bug 成為正式規則。

這次經驗讓他們把優先順序從：

```text
Rule Consistency
+ Balance Correctness
        ↓
修掉異常
```

改成：

```text
玩家是否需要投入足夠成本找到組合？
        +
結果是否真的產生有趣體驗？
        ↓
即使很強，也可以保留
```

這並不是「完全不要 Balance」，而是承認 Balance 只是服務體驗的一種手段。

## Broken Build 的樂趣來自「我發現了它」

開發者把玩家最終做到極端強度的感覺描述為「自己把遊戲破壞掉」或「超越遊戲」。

這裡的差異很重要。如果遊戲一開始直接給玩家一個無敵按鈕，通常沒有同樣的快感；真正有價值的是玩家先理解多個局部規則，再發現它們組合後產生遠超預期的結果。

文章另一個例子是角色空殻：他的固有 Passive 會把 Attack Speed Bonus 轉成 Attack Power。玩家卻發現可以利用一個帶失敗機率的強化系統，故意讓強化失敗並刪除固有 Passive，反過來恢復高速攻擊 Build。

這種玩法的內容其實不是單一 Skill，而是規則之間的交叉：

```text
角色固有規則
    ×
裝備／記憶規則
    ×
強化失敗規則
        ↓
設計者沒有直接寫出的 Build
```

系統因此不只是提供「選項」，而是提供玩家可以推理的規則空間。

## 合作角色分工：讓角色有功能，但不要把玩家鎖成職業

團隊最初希望保留 MOBA 中角色互補的樂趣，同時減少 PvP 與隊友帶來的壓力。因此遊戲仍有戰鬥、治療等不同功能，但刻意讓角色分工保持彈性。

他們的理由很直接：如果玩家感到「隊伍需要我，所以我必須一直做這件事」，角色差異就可能從合作樂趣變成義務。

這和 Broken Build 的哲學其實相通：系統建立不同方向的誘因，但不急著把玩家壓進設計者認為唯一正確的玩法。

## 長期 Demo 被當成設計研究工具

《Shape of Dreams》在正式推出前讓 Demo 運作了一年以上，而且做過數十次更新。團隊承認，當時兩位創辦人仍是缺乏經驗的大學生，無法只靠自己的企劃能力判斷遊戲是否真的好玩，因此刻意把大量內容放進 Demo，以真實玩家回饋改善 WASD 操作與 Map 等系統。

這裡的流程接近：

```text
設計假設
   ↓
公開 Demo
   ↓
玩家實際找到玩法／問題
   ↓
團隊觀察「玩家在做甚麼」
   ↓
修改系統甚至修改設計哲學
```

重要的是玩家回饋並不只是 Bug List。無限 Parry 的案例恰好說明：玩家可以透過行為告訴設計者，某個「錯誤」其實已經承載了樂趣。

## 閱讀時需要知道的前提

這是一篇開發者訪談，不是系統性 Balance Postmortem。文章沒有提供 Build 使用率、Win Rate、難度分布或完整數值，因此不能從中推出「越不平衡越好」。

更準確的理解是：對以組合發現為核心的 Roguelite，**局部失衡可能本身就是玩家追求的 payoff**；是否修正應同時考慮取得難度、重現成本、是否壓縮其他玩法，以及它帶來的樂趣。

## 我的筆記與延伸

這篇最有意思的地方，是把 Bug 和 Feature 的邊界從「是否符合設計文件」移到「它在玩家體驗中扮演甚麼功能」。

對高度 Systemic 的遊戲而言，設計者不可能窮舉所有規則組合。如果系統真正允許 Emergent Gameplay，那麼一部分好玩法理論上就必然是設計者沒有直接設計過的。這時 QA／Balance 的工作不應只是把所有偏離預期的行為消掉，而要先分類：

```text
破壞存檔／卡死／無法逆轉
→ 明確錯誤

讓單一策略永久支配所有選擇
→ 可能需要 Balance

難以構成、很好玩、產生新的策略空間
→ 可能值得正式化
```

當然，最後一類仍可能因 PvP、公平競爭或 Live Service Economy 而不能保留。《Shape of Dreams》是 PvE Roguelite，玩家把系統「玩壞」造成的外部成本較低，這是它能採取這種哲學的重要前提。
