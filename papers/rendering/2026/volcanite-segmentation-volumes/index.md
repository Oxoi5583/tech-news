# Volcanite: Commodity-Hardware Segmentation Volume Visualization for Connectomics and Beyond

## 先用一個例子理解

腦科學家用電子顯微鏡掃描一小塊大腦組織，再把每個體素（三維像素）標記為「屬於第幾號神經細胞」。這樣的**分割體積**（segmentation volume）可以有 5,550 億個體素、1,340 萬種不同標籤，原始資料超過 2 TB。

過去要看這種資料，通常得先把每個細胞轉成三角網格，而 Neuroglancer 為 H01 人類皮質資料產生網格要超過一星期，而且簡化網格會抹掉細節。Volcanite 則直接在一台 Ryzen 7 5800X + RTX 4070 Ti Super（16 GiB VRAM）的桌機上，約兩小時預處理後，以每秒 66 幀直接瀏覽整份 2.2 TB 資料，並帶陰影與全域光照。

對遊戲開發者來說，換個角度看：這就是一個**每格存「材質或物件 ID」的超大體素世界**，而且在一般遊戲級 GPU 上能即時看。

## 原本的做法有甚麼困難

- **標籤不能平均**：一般密度資料（煙、CT 灰階）可以做 mipmap 平均；但「第 17 號細胞」和「第 42 號細胞」平均起來沒有意義。遠處的低解析度層只能取眾數之類的代表標籤。
- **標籤種類極多**：傳統工具（VTK / ParaView）只支援 32 種類別標籤直接渲染，資料太大時直接放不進記憶體。
- **轉網格昂貴且失真**：網格化要大量預處理，儲存量比壓縮體積大好幾個數量級，還會平滑掉體素層級的錯誤——而科學家恰恰需要看到這些錯誤。

## 它是怎樣做到的

### 1. CSGV 壓縮：用「複製鄰居標籤」編碼

Volcanite 使用作者先前發表的 **CSGV**（Fast Compressed Segmentation Volumes，IEEE VIS 2023）格式並加以改進：

- 體積切成 32³ 磚塊（大資料用 64³）；
- 每個磚塊由粗到細建立多層次（LOD）八叉樹式網格；
- 每個節點有一個「stop bit」：若整個子區域同一標籤，就標記後不再細分；
- 否則每個節點記錄一個**操作**：從某個鄰近節點複製標籤，或從磚塊的**調色盤**（palette，本磚塊出現過的標籤清單）讀一個新標籤；
- 操作串流最後再做熵編碼（依出現頻率用更短的位元表示常見符號）。

本文把原本最長 4 位元的調色盤回溯參照改為不限長度，避免調色盤中出現重複標籤。結果壓縮後大小介於原始資料的 2.849%（Fabricval）到 0.046%（H01BV），大約每體素 0.5–1.5 bit。

### 2. GPU 快取與按需解壓

- 每幀流程是 Request → Provision → Assign → Decode → Render → Resolve，全在 GPU 上以多次 compute dispatch 完成，**同一幀內沒有 GPU→CPU 同步**；
- 只解壓畫面上看得見的磚塊，遠處磚塊請求較粗的 LOD；
- 最細一層 LOD 佔總壓縮量 45%–68%，單獨存放、需要時才串流上 GPU。對 H01WM，這讓常駐的壓縮資料量減少 65.7%；
- 解壓後的磚塊以**調色盤索引**形式存入快取（例如只需幾個 bit 指到本磚塊調色盤），而不是每體素 32-bit 標籤，令同樣 VRAM 能快取更多磚塊；
- Shader 依每份資料即時編譯，把許多參數當編譯期常數，去掉用不到的分支。

### 3. 渲染

- 逐體素光線步進（ray marching）；為了在極大座標下保持數值穩定，把位置拆成「整數體素座標 + 浮點次體素偏移」；
- 四種著色模式可即時切換：簡單局部光照、一條陰影光線、環境光遮蔽、最多 32 次反彈的路徑追蹤；
- 路徑追蹤結果以 edge-avoiding À-trous 小波降噪器處理，並擴充為同時做升取樣：每 2²、4² 或 8² 像素區塊只真正渲染一個像素。

## 與現有方法的差別

| 項目 | VTK / ParaView | Neuroglancer（網格） | Volcanite |
| --- | --- | --- | --- |
| 標籤數量 | 32 類 | 不限 | 不限 |
| 大資料 | 記憶體不足 | 需網格化 | 壓縮串流直接渲染 |
| H01 預處理 | — | 超過一星期 | 不到兩小時 |
| 體素精度 | 取樣不準 | 網格簡化失真 | 保留體素標籤 |
| 全域光照 | 無 | 無 | 路徑追蹤 |

## 實驗結果與限制

- 測試機：AMD Ryzen 7 5800X、48 GiB RAM、RTX 4070 Ti Super 16 GiB、NVMe SSD、Ubuntu 24.04。
- 13 份跨領域資料（連接體學、材料、生物），由 72 MB 到超過 2 TB。
- 互動幀時間約 2–29 ms；論文摘要稱最多可在 100 FPS 下渲染約五千億體素；H01WM（5.55×10¹¹ 體素）達 66 FPS。幀率與著色模式、視角和解析度有關，不同資料之間不能直接比較。
- 作者提供下載資料、無頭模式執行及重建所有圖表的腳本。
- **限制**：目標是 teravoxel 級，完整 petascale 資料不在範圍內；尚未支援從遠端伺服器按需串流；標籤無法像密度一樣預濾波，遠處只能以多解析度階層近似；**資料是靜態的**，論文沒有處理即時編輯。

## 可以怎樣用在遊戲裡

**原文實證**：只在科學視覺化資料上驗證，沒有任何遊戲用途的實驗。這是「可合理移植但未驗證」的跨領域成果。

**我的延伸構想（未驗證）**：

1. **超大體素世界的材質 ID 儲存**：Minecraft、Teardown 類遊戲或可破壞地形，本質上也是「每格一個材質／方塊 ID」的分割體積。CSGV 的「複製鄰居標籤 + 磚塊調色盤 + 多層 LOD」可作為世界存檔或串流格式，與 SVDAG、HashDAG 等以幾何去重為主的結構互補——後者擅長重複形狀，CSGV 擅長大片同標籤區域與大量不同 ID。
2. **調色盤快取**：解壓後以磚塊局部調色盤索引存放，是一個容易單獨採用的技巧，能在不改渲染器的情況下讓體素快取容量倍增。
3. **遠景 LOD**：「標籤不能平均」的問題在體素遊戲遠景同樣存在，論文用眾數代表的多解析度階層是一個可參考的基準。
4. **醫學／科學題材內容**：直接用真實分割資料製作教育或解謎遊戲場景。

主要障礙：

- **可編輯性**：CSGV 是整塊磚的串流編碼，修改一個體素就要重新編碼整個磚塊（32³ 或 64³）。遊戲需要設計「髒磚」緩衝、背景重新壓縮，並量測每秒可承受的編輯量。
- **幀預算**：2–29 ms 是整個 GPU 都給體積渲染的情況；遊戲還要畫角色、特效、UI。
- **路徑追蹤成本**：遊戲大概只會用陰影光線或 AO 模式。

## 想實作時再看

最小原型：

```text
1. 以 Volcanite 開源碼把一張 Minecraft 風格的世界匯出成標籤體積（每格方塊 ID），壓縮後比較大小與原始區塊檔、SVDAG。
2. 只抽出「磚塊調色盤 + 調色盤索引快取」一部分，放進自家體素渲染器，量快取可容納磚數的變化。
3. 做編輯實驗：每秒隨機修改 N 個體素，標記髒磚、在背景 thread 重新編碼，量延遲與吞吐。
```

閱讀建議：先看壓縮格式與快取管理兩節；渲染章節中「大座標數值穩定」與「降噪兼升取樣」兩個細節對大型世界渲染也有參考價值。若想理解編碼本身，應同時讀 CSGV 原論文（arXiv 2308.16619）。
