# GeoTrussRover: Morphological Computation with Contact-Semantic Control Primitives

## 先用一個例子理解

想像一台車的車身不是固定鐵箱，而是由一批能伸縮的桿件組成。遇到階梯時，它可以抬高前半部、改變車身長度，再把後半部帶上去。

難題是：階梯每高一點，是否就要重新計算每根桿件在整段動作中應該伸多長？

這篇研究嘗試保存「先建立前方支撐，再把後半部抬上去」這一類策略，然後依照新障礙的尺寸調整具體動作。

## 原本的做法有甚麼困難

研究使用 **可變幾何桁架（Variable-Geometry Truss，VGT）**作為車體。「桁架」是由許多桿件連成的承重骨架；這裡的桿件能伸縮，所以骨架本身也能改變形狀。

論文系統有 21 根結構桿件，還要與輪子配合。如果每遇到新障礙，都從頭計算所有桿件和輪子接下來的動作，需要考慮的變數會很多。

其中 **致動器（actuator）**就是把控制命令變成實際動作的裝置，例如推動伸縮桿的馬達。

## 它是怎樣做到的

1. **先完整算出一個成功例子。**讓機器人跨過一個已知障礙，取得整段動作。
2. **把動作整理成四種可重用的基本策略。**重點是不同階段由哪裡接觸地面、哪部分支撐、身體如何配合變形，而不只是記下每根桿的長度。
3. **遇到相似障礙時，調整已有策略。**例如階梯變矮，但前後輪接觸障礙的關係仍相似，就沿用原有策略，再算出適合新尺寸的伸縮量。
4. **只有做不到的階段才重新計算。**最後由控制器追蹤目標，修正桿件和輪子的動作誤差。

論文把這些基本策略叫做 **contact-semantic primitives**，可理解為「依照接觸和支撐用途整理的基本動作」。**接觸拓撲（contact topology）**則是指哪些部位接觸哪些表面，以及這些關係如何安排，不只是障礙的高度。

調整動作時還要遵守限制，例如桿件不能伸得無限長、機體需要維持可行的支撐。論文的 **physics-constrained projection** 就是把原來想做的動作，修正成符合這些幾何與物理限制的動作。

## 與固定動畫有甚麼差別

| 做法 | 階梯高度改變時怎樣處理 |
| --- | --- |
| 播放固定動畫 | 原來的腳或輪子位置可能對不上，需要另外修正 |
| 從頭規劃整段動作 | 再次計算所有桿件與輪子如何移動 |
| 這篇方法 | 優先沿用支撐和變形策略，再依新尺寸計算具體動作 |

所以它保存的比較像「跨障礙的做法」，而不是一段不能改動的動作錄影。不過調整後仍然需要求解和控制，並非直接播放就完成。

## 實驗結果與限制

論文把跨越 **0.10 公尺**階梯的動作，轉用到 **0.075 公尺**的階梯。相較重新計算完整動作，作者報告「評估候選解好壞的次數」減少約 **63.7%**。

這個指標原文叫 **objective-function evaluations**。它表示求解過程少做了多少次評分，**不等於整個程式必然快了 63.7%**。

作者分析的可行階梯高度約為 0.10–0.46 公尺，相當於輪子半徑的 1.08–4.97 倍；實際電動原型跨越的高度約為輪子半徑的 2.11 倍。分析範圍與實機展示應分開看。

限制包括：

- 基本策略針對這種伸縮骨架與輪子的組合設計，並不是通用機甲控制器。
- 接觸關係相似時較容易重用；障礙類型完全不同，可能要先取得新的成功動作。
- 仍需計算受限制的動作，不能省去底層控制。
- 換成重型機甲後，還要重新考慮重量、碰撞、結構負載及馬達能力。

## 可以怎樣用在遊戲裡

以下是機甲遊戲的延伸構想：先決定「哪裡需要支撐、身體要變成甚麼形狀」，再讓各個關節和伸縮裝置共同完成。

例如跨過一道高障礙，可以先建立前方支撐，抬起並伸展軀幹，再移動重心，最後把後半部帶過去。不同障礙尺寸共用大致策略，實際桿長和身體角度由控制器決定。

如果機甲允許更換腿長、輪子位置或額外支撐臂，這种做法值得試驗。但論文並未證明它能直接控制任意玩家組裝的機甲。

## 想實作時再看

先做簡單的平面原型即可：

1. 用四個連接點、4–6 根伸縮桿和兩個輪子建立機體。
2. 手動定義「接近障礙」「前方支撐」「抬起後部」三個階段。這是試作簡化，不是論文四種策略的逐一重現。
3. 每階段只描述身體角度、前後高度，以及前後輪各自承擔多少重量。
4. 由**約束求解器**計算實際桿長，也就是找出同時符合目標和限制的一組數值。
5. 改變階梯高度，觀察同一組策略能否繼續使用。

論文的 **QP（二次規劃）**是一種最佳化方法：用平方誤差等方式衡量動作與目標的差距，在限制內尋找較好的控制量。這裡的 full-space QP 表示最後仍要一起處理完整機體的控制變數。

## 個人筆記

值得留下的想法是：**「先支撐哪裡，再把身體移去哪裡」可以重用，不必連每個馬達的動作都固定下來。**
